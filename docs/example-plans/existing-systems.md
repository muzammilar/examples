# Next workloads for systems already in the repository

Pick a single question from this page when revisiting a system. Each link points to the existing setup or measured workload to extend. Unchecked entries describe **new work**. Check the local README before choosing a case so that an already measured restart or benchmark stays credited.

## Transactions, replication and routing

- [ ] **Aerospike — concurrent inventory reservations.** Two clients update a versioned record with generation checks on the existing Community cluster. Lose a reply during a member change and reconcile reservations per key against the client log. Record the configured AP policy and storage mode before interpreting survival. [Existing topology](../../aerospike/)
- [ ] **CockroachDB — retry a transfer across ranges.** Place debit and credit accounts in different ranges and interrupt the SQL gateway around commit. Reissue the same application transfer ID, then use independent reads to verify one receipt, balanced accounts and the disposition of unknown outcomes. [Existing deployments](../../cockroachdb/)
- [ ] **FoundationDB — ambiguous seat booking.** Put a reservation, seat counter and operation receipt in one transaction. Disconnect the client during commit and retry through the normal retry loop while another customer requests the last seat. Verify the winning reservation and one debit by ID. [Existing cluster](../../foundationdb/docker-compose-cluster/) · [Transaction retry semantics](https://apple.github.io/foundationdb/developer-guide.html)
- [ ] **TigerBeetle — race post, void and expiry across failover.** Bring the existing payment-hold workload onto a replicated ledger. Retry the same posted or voided transfer IDs across primary loss and read every pending/posted balance from a fresh client. Each hold must have at most one effective settlement. [Payment fixture](../../tigerbeetle/payments-ledger/) · [Two-phase transfers](https://docs.tigerbeetle.com/coding/two-phase-transfers/)
- [ ] **TiDB — historical inventory during a region move.** Capture a timestamp between two known inventory revisions, move a region leader, and read at that timestamp alongside current transactions. Verify the exact old and new bodies and the explicit outcome of reads beyond the GC window. [Existing PD/TiKV cluster](../../tidb/docker-compose-cluster/) · [Historical reads](https://docs.pingcap.com/tidb/v8.1/as-of-timestamp/)
- [ ] **TiKV — transaction resolution after a client crash.** Kill a TxnKV client with a cross-region transfer in flight and have another client contend on those keys. Verify both account versions and the receipt after lock resolution. Use RawKV only as a separate single-key control. [Existing RawKV/TxnKV examples](../../tikv/)
- [ ] **YugabyteDB — transfers during tablet-leader changes.** Run cross-tablet YSQL transfers while moving leadership in the RF3 cluster. A fresh session checks both legs, balance and unique retry IDs. A separate YCQL profile should state its transaction contract before reusing any invariant. [YSQL and YCQL topology](../../yugabyte/)
- [ ] **YDB — transaction retry through a lost compute node.** Write one order and one inventory decrement across partitions while terminating the dynamic node serving the session. Reconnect through a surviving endpoint and validate every order, retry receipt and resulting quantity against the external history. [Storage and compute roles](../../ydb/docker-compose-cluster/)
- [ ] **OceanBase — live HTAP on a replicated tenant.** Move the existing single-observer orders workload to the zoned cluster. Fail a leader while tenants update orders and run reports. Reconcile committed versions at a known cut and record the impact on fresh OLTP reads separately from analytical scans. [Orders workload](../../oceanbase/htap-orders/) · [Cluster](../../oceanbase/docker-compose-cluster/)
- [ ] **SingleStore — routing and redundancy of leaf partitions.** In a licensed replicated topology, run customer-local lookups and cross-customer aggregates while removing one leaf. Check the native partition placement and each acknowledged order body after recovery. Keep the developer image’s one-leaf case as a SQL baseline. [Existing editions and roles](../../singlestore/)
- [ ] **RonDB — feature-vector freshness during a data-node rebuild.** Send versioned updates while the existing feature-store reader issues keyed lookups. Replace one member of a replicated node group and compare returned feature bodies with acknowledged revisions, including a read after redundancy is restored. [Online feature store](../../rondb/online-feature-store/)
- [ ] **Tarantool — wallet operations across a vshard bucket move.** Start with wallets whose debit and fee can be committed by the same storage replicaset. Move their bucket while retries hit the router. Verify operation receipts, balances and final bucket ownership. Treat transfers spanning replica sets as a separate application protocol. [Wallets](../../tarantool/wallet-transfers/) · [vshard cluster](../../tarantool/vshard-cluster/)
- [ ] **ScyllaDB — deletes on a lagging replica.** At explicit RF and consistency levels, isolate one replica during updates and deletes, heal it and run the supported repair procedure. Check deleted keys for resurrection and compare surviving values after repair. Measure hint delivery and repair separately. [Cluster](../../scylladb/docker-compose-cluster/) · [Hinted handoff](https://docs.scylladb.com/manual/branch-2025.1/architecture/anti-entropy/hinted-handoff.html)

For **PostgreSQL, MySQL, their sharding systems, Neon, StarRocks and CedarDB**, use the [relational designs](relational-and-analytical.md). PostgreSQL customer sharding, PgDog pooling, Vitess, NDB and Citus already have different topologies and recorded failure histories. Preserve those distinctions when selecting a control.

## Cache, search and graphs

- [ ] **Dragonfly — interrupt a native slot migration.** Move a hot tenant between real shards with pooled clients sending versioned values. Interrupt the migration, discover the current owner and resume. Compare each ACK against values read through both a fresh cluster client and the reported owner. [Native and emulated modes](../../dragonfly/docker-compose-cluster/)
- [ ] **Valkey — stale clients during operator resharding.** Keep an old connection open across a shard-count change with a concentrated slot workload. Record redirects and retries, then reconcile per-key versions and verify complete slot coverage. Exercise replica promotion in a separate phase to expose the asynchronous ACK window. [Operator example](../../valkey/valkey-operator/)
- [ ] **Skytable — sessions across process recovery.** Kill the single server after a mixture of session extensions and rate-limit debits, then read the persisted records with a new client. Check which acknowledged counters and expiry decisions survived under the configured durability policy. [Session workload and topology limits](../../skytable/session-store/)
- [ ] **Elasticsearch — stable pagination during changes.** Traverse an ordered catalog with a point-in-time search and a deterministic tiebreaker while documents are updated or removed. Restart a node, open a fresh search and check the old and new result sets against their own snapshots. Record expired search contexts explicitly. [Existing Elasticsearch examples](../../elasticsearch/) · [Point-in-time pagination](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results)
- [ ] **Manticore — log rotation and flush under live search.** Feed delayed documents into an RT table while rotating/flushing chunks. Interrupt one member, then check match sets, tags and facets against the immutable log IDs before and after replication catches up. [Log search](../../manticore/log-search/) · [Cluster](../../manticore/docker-compose-cluster/)
- [ ] **Typesense — isolate one customer shard group.** Partition one Raft group while the application fans a search across all customer shards. Compare healthy tenants’ results and explicit partial-result/error behavior with a corpus manifest. After healing, verify each shard’s versions and the merged top results. [Existing application-managed sharding](../../typesense/product-search/)
- [ ] **Vespa — document updates during redistribution.** In the grouped topology, update documents chosen from every content partition while a node is unavailable. Compare ranked results against a frozen query set and independently fetch document versions from their recovered locations. Record partial coverage returned by queries. [Grouped serving topology](../../vespa/phased-product-search/)
- [ ] **Qdrant — move a hot tenant shard.** Transfer a shard during payload-filtered vector updates and compare exact retrieved IDs, payloads and versions after cutover. Use a brute-force scorer on the same visible corpus for recall. Keep quantizer comparisons separate from migration-induced availability. [TurboQuant and prior results](../../qdrant/turboquant/)
- [ ] **Milvus — freshness through growing-to-sealed segments.** Add vectors with known nearest neighbors, run filtered searches under two declared consistency levels, and interrupt index construction or loading. Compare exact scalar IDs and independent recall before and after sealing. First use the standalone fixture, then a separately budgeted distributed deployment. [Existing standalone profiles](../../milvus/) · [Read consistency](https://milvus.io/docs/v2.6.x/tune_consistency.md)
- [ ] **Weaviate — vector visibility during replica disagreement.** Update an object and its vector while one replica is isolated. Compare point reads at each selected consistency level with ranked search results and tombstones after healing. Recompute neighbors offline and record whether the API supports the same consistency controls on each path. [Existing sharded cluster](../../weaviate/) · [Consistency semantics](https://docs.weaviate.io/weaviate/concepts/replication-architecture/consistency)
- [ ] **LanceDB — retained version through compaction and restore.** Pin a reader to a catalog version while the sole writer appends and compacts. Restore to an independent directory with the original hidden, then verify old/new vectors and filtered top-k with fresh readers. The serving workers share one underlying catalog. [Versioned retrieval lab](../../lancedb/versioned-product-search/)
- [ ] **ArangoDB — traversal across a failed DB-server.** Use sharded vertex and edge collections for a known transfer graph. Stop a DB-server during edge updates, then compare exact bounded paths and document revisions across coordinators after recovery. State the atomicity scope for cross-collection changes. [Existing agents, coordinators and DB-servers](../../arrangodb/docker-compose-cluster/)
- [ ] **Memgraph — stale fraud decisions after manual promotion.** Extend the payment graph with witnessed edges during a SYNC or ASYNC replica outage in separate profiles. Fence the old MAIN, promote according to the Community runbook and compare complete fraud-ring memberships with an independent graph traversal. [Fraud workload](../../memgraph/fraud-detection/) · [Edition and promotion behavior](../../memgraph/)
- [ ] **NebulaGraph — storage partition leader loss.** Expand the single storage service into a verified replicated graph space. Load known cross-partition paths, remove one storage leader and check exact edge IDs and shortest-path lengths before and after leadership moves. Observe metadata availability separately. [Existing deployment](../../nebula-graph/)
- [ ] **Neo4j — bookmarked reads after leader loss.** In the existing edition-gated cluster, commit an edge, keep its bookmark and read through a routed follower after the writer disconnects. Check that a successful bookmarked read includes the edge and compare unbookmarked visibility and errors separately. [Cluster and license](../../neo4j/docker-compose-cluster/) · [Bookmark semantics](https://neo4j.com/docs/query-api/current/bookmarks/)

## Streaming, time and orchestration

- [ ] **Kafka — mirror cutover with a partition-count change.** Extend the checkpoint-backed cutover lab with a newly added partition while the consumer group is active. Fence the old producer at cutover, translate group progress and reconcile order IDs and duplicates per partition. [Existing cutover evidence](../../kafka/cross-cluster-mirroring/)
- [ ] **Redpanda — transactional consumer visibility.** Publish numbered pairs in transactions, lose the producer’s reply around commit and change a partition leader. Compare read-committed output to the transaction history and a separate uncommitted reader. Repeat on Kafka using the same API and ACK settings. [Existing broker cluster](../../redpanda/docker-compose-cluster/)
- [ ] **NATS JetStream — crash after processing but before acknowledging.** A durable pull consumer records a side effect in a local transactional sink, then exits before its ACK. Verify redelivery, duplicate attempts and one final effect per message across stream-leader failover. Keep Core NATS delivery as a distinct contract. [Cluster](../../nats.io/docker-compose-cluster/) · [Consumer acknowledgements](https://docs.nats.io/nats-concepts/jetstream/consumers)
- [ ] **RisingWave — recover a lagging CDC source.** Interrupt ingestion while PostgreSQL receives creates, corrections and cancels. Track the retained WAL and consumer position, then compare every materialized customer total with a source snapshot at a known watermark. Repeat with an explicit retention limit to expose when a resnapshot is needed. [Existing CDC metrics workload](../../risingwave/cdc-order-metrics/)
- [ ] **QuestDB — out-of-order market corrections.** Replay duplicated quotes and revised trades into the WAL table, crash the server during ingestion and read the settled data over a fresh session. Verify complete rows and recompute bars and as-of matches against a sorted event journal. [Existing market feed](../../questdb/market-data/) · [Deduplication keys](https://questdb.com/docs/concepts/deduplication/)
- [ ] **kdb+ — historical partition publication.** Feed corrected trades into the licensed local q setup and interrupt publication of a date partition. Reopen with fresh readers and verify the quoted prices at trade time against a timestamp-ordered fixture. Include a partition manifest to detect partial publication. [Capital-markets workload and license](../../kdb/)
- [ ] **TimescaleDB — late data versus aggregate refresh and retention.** Submit corrected fleet samples on both sides of a refresh boundary while the retention policy runs. After a Patroni switchover, compare each bucket with a raw source ledger under the declared refresh policy. Report which historical corrections can still be recomputed. [Fleet example and supported topologies](../../timescaledb/)
- [ ] **InfluxDB — visibility across WAL and Parquet publication.** Use the existing v3 Core profile with witnessed line-protocol writes and tag/field values. Interrupt object-store access during persistence, restore it and compare recent and older SQL results to accepted points, including repeated point keys. [Core versus historical cluster profiles](../../influxdb/)
- [ ] **Airflow — replay an interrupted interval.** Terminate a worker after an ETL task publishes output and before it records completion. Let the scheduler retry and backfill an overlapping interval. Compare output keys and checksums to the input manifest and distinguish successful task attempts from unique published partitions. [Compose and TaskFlow fixture](../../airflow/basic/)

For **GreptimeDB and the Victoria/Grafana stack** use the [accepted comparison contract](../../observability/README.md#greptimedb-vs-victoria-planned-comparison). For **DuckDB, Iceberg, ClickHouse, Garage, SeaweedFS, RustFS, Ceph, ZFS and self-hosted Tigris**, pick a [storage design](storage-and-lakehouse.md). **Rayforce** retains its [failed integrity cases](../../rayforce/duckdb-comparison/) alongside the proposed recovery work. Kubernetes, QEMU, Vagrant and Ansible are deployment tools in this inventory. Their system-specific operating tests live with the database that owns the lab.
