# Storage engines, table formats and catalogs

Each unchecked item is a proposed example. Use an example-owned local object store and credentials. Record its allocation, durability and outages separately from the client, catalog and table format. The [existing S3 results](../../object-storage/) and [Iceberg results](../../iceberg/) give the starting configurations.

## Columnar compression and file performance

- [ ] **CSV vs Parquet vs Arrow IPC/Feather V2 vs Vortex.** Use identical typed rows,

  cold/warm distinctions and interrupted/corrupt-file recovery. Keep Arrow memory

## Tables and catalogs

- [ ] **Apache Hudi — corrections during compaction (new).** Feed identical order updates, deletes and late arrivals to copy-on-write and merge-on-read tables. Interrupt a merge-on-read compaction while ingest continues, then compare both snapshots to a source ledger at the same source offset, recording each table’s own completed instant. Measure the separate freshness of the read-optimized view. [Table types](https://hudi.apache.org/docs/table_types/) · [Compaction](https://hudi.apache.org/docs/compaction/)
- [ ] **Apache Paimon — inventory changelog.** Send out-of-order stock corrections through Flink into a primary-key table on SeaweedFS. Declare the sequence field and changelog producer, interrupt compaction, then compare a supported reader’s inventory per SKU and a downstream changelog consumer against the input revisions. Use the same correction stream for Iceberg. [Primary-key tables](https://paimon.apache.org/docs/master/primary-key-table/) · [Compaction](https://paimon.apache.org/docs/master/primary-key-table/compaction/)
- [ ] **Delta Lake — which version can another engine see?** Let Spark publish appends, updates and deletes to a local Delta table. Interrupt a write between data-file creation and log publication, then read the last two committed versions in Spark and with a compatible DuckDB reader. Compare bodies and nulls by ID and record unsupported protocol features. [Delta transaction semantics](https://docs.delta.io/concurrency-control/) · [DuckDB Delta extension](https://duckdb.org/docs/stable/core_extensions/delta)
- [ ] **Apache Polaris — catalog loss with data intact.** Two independent Iceberg REST clients append to the same table through Polaris backed by persistent catalog storage. Restart the catalog around publication and reconcile the old and current snapshots against acknowledged batches. Then restore the catalog to a fresh instance and test what the surviving objects alone can recover. [Polaris](https://polaris.apache.org/) · [Iceberg REST specification](https://iceberg.apache.org/rest-catalog-spec/)
- [ ] **Project Nessie — publish a corrected dataset across tables.** Build order and payment corrections on a branch while a reader queries the main reference. Introduce a conflicting main-branch change before merge. Reopen each reference at its recorded hash and verify cross-table balances, including after a catalog restart. [Iceberg REST and references](https://projectnessie.org/guides/iceberg-rest/)
- [ ] **DuckLake — two writers, one catalog (explicitly deferred).** Use independent DuckDB processes against a PostgreSQL DuckLake catalog and a local warehouse. Compare disjoint appends with overlapping updates, lose a commit reply, then inspect the catalog snapshots from a third process. Classify conflicts, duplicated effects and missing rows by operation ID. [Transactions](https://ducklake.select/docs/stable/duckdb/advanced_features/transactions) · [Conflict resolution](https://www.ducklake.select/docs/stable/duckdb/advanced_features/conflict_resolution)
- [ ] **Hoglake — delayed changefeed consumer (documentation only).** Map how Parquet upload, PostgreSQL metadata commit, consumer offsets and expiry interact. Design a native Trino snapshot read and a stalled consumer across compaction, with expected row IDs and deletion vectors at each snapshot. Keep the Iceberg REST facade gated on its actual implementation. [Upstream components and commit path](https://github.com/PostHog/hoglake)

## Outstanding Iceberg paths

- [ ] **Native DuckDB to Iceberg — maintenance with a moving head.** Extend the controlled conflict case to a continuous writer and a reader pinned before the rewrite. Interrupt the maintenance client before and after catalog publication. Account for every committed append, check snapshot ancestry and measure how long either writer waits to make progress. [Existing conflict evidence](../../iceberg/multi-system/projects/duckdb-iceberg/docs/DUCKDB_CONFLICTS.md)
- [ ] **Iceberg retention and partition evolution.** Change the partition spec after an append, update or delete a known subset through a supporting engine, and read both generations by ID. Hold a retained snapshot while expiring older snapshots, then inspect which objects remain reachable before scheduling orphan cleanup. [Iceberg specification](https://iceberg.apache.org/spec/) · [Maintenance](https://iceberg.apache.org/docs/latest/maintenance/)
- [ ] **DuckDB via HTTP to ClickHouse and Iceberg — lost insert reply.** Drop a response after ClickHouse accepts a numbered batch and before DuckDB records success. Reconcile physical rows, logical IDs and nullable, decimal and timestamp values before any retry, then repeat with the catalog or object store unavailable. Use the healthy two-million-row case as the control. [HTTP project and evidence](../../iceberg/multi-system/projects/duckdb-clickhouse/http/)
- [ ] **Rejected scanner and manifest interoperability — diagnostic only.** Pin a single generated input and compare the streamed predicate, materialized predicate and independent native result. Separately inspect the failing manifest against the format specification and test it in two readers; assign a cause only if the reduced case isolates it. [Scanner failure](../../iceberg/multi-system/projects/duckdb-clickhouse/clickhouse-scanner/) · [Manifest investigation](../../iceberg/multi-system/projects/manifest-interop/) · [Specification](https://iceberg.apache.org/spec/)
- [ ] **Trino and native serving/archive — interruption at publication.** In the [Trino example](../../iceberg/trino-minio/), lose the response to a snapshot commit and verify the transaction from a fresh reader. In the [ClickHouse archive](../../clickhouse/iceberg/), hold a reader on the old snapshot during archive retry and source expiry; prove each acknowledged body remains reachable through the handoff.

## Object and filesystem storage

- [ ] **Apache Ozone — object data versus namespace availability (new).** Use its S3 Gateway, Ozone Managers, Storage Container Managers and DataNodes with a verified three-copy policy. In separate phases lose an OM leader and a DataNode under multipart traffic. Verify each completed object's bytes via a fresh gateway, incomplete uploads, restored container placement and time to redundancy. [S3 gateway](https://ozone.apache.org/docs/core-concepts/architecture/s3-gateway/) · [Upstream Compose layouts](https://github.com/apache/ozone/tree/master/hadoop-ozone/dist/src/main/compose)
- [ ] **SeaweedFS — warm volume erasure coding.** Seal a volume with known objects, encode it using the supported layout, identify the physical fragments and lose one within tolerance. Read every original body during reconstruction and after repair. Publish temporary and settled space, and separate read-only encoded data from the writable replicated volume. [Encoding implementation](https://github.com/seaweedfs/seaweedfs/blob/master/weed/shell/command_ec_encode.go)
- [ ] **SeaweedFS — asynchronous second cluster.** Run two independently owned filer/storage stacks, stop the follower synchronization process during overwrites and deletes, and resume from its checkpoint. Read both clusters directly to quantify stale versions and verify final bodies and tombstones. Start with one writer domain. [Filer synchronization](https://github.com/seaweedfs/seaweedfs/wiki/Filer-Active-Active-cross-cluster-continuous-synchronization)
- [ ] **Garage, RustFS and Ceph RGW — interrupted multipart completion.** Reuse each store's existing cluster and witness. Lose a gateway immediately around completion, list unfinished uploads, then reconcile object versions and full-body checksums before retry. For Ceph also observe placement-group recovery, for RustFS inspect rebuilt shards, and for Garage verify placement after catch-up. [Existing configurations and limits](../../object-storage/)
- [ ] **Self-hosted Tigris — blocked.** The entrance criterion is a supported, redistributable or locally licensed **storage server**. If one becomes available, use the same local multipart and conditional-update history as Garage, checking DuckDB range reads after a lost reply. TAG and ocache serve different roles. [Repository investigation](../../tigris/) · [Upstream service and SDK](https://github.com/tigrisdata/storage)
- [ ] **Blob or metadata pointer?** Compare 1–4 MiB bodies in SeaweedFS, Aerospike and ScyllaDB at verified record/mutation limits. In a fourth profile interrupt between immutable object PUT and pointer publication in ScyllaDB. Check for missing bodies, stale pointers and collectable orphans using digests after retry. [Aerospike record limits](https://aerospike.com/docs/database/reference/config/?show-removed=1) · [ScyllaDB configuration](https://docs.scylladb.com/manual/stable/reference/configuration-parameters.html)
- [ ] **OpenZFS and DuckDB/ZFS — prove restore from the shipped stream.** Restore a preserved full plus incremental stream into a fresh guest-owned pool with the source unavailable. Verify snapshot lineage, a manifest of file hashes and DuckDB row bodies at the last replicated watermark. Count newer acknowledged rows as asynchronous RPO. [ZFS lab](../../zfs/storage-lab/) · [DuckDB lab](../../duckdb/zfs-recovery/) · [Receive semantics](https://openzfs.github.io/openzfs-docs/man/master/8/zfs-receive.8.html)
- [ ] **DAOS — layout and rebuild boundaries.** First run one emulated Linux engine for KV and POSIX readback. Only test replicated or erasure-coded object rebuild with enough independently placed engine ranks for the selected object class. Exclude a rank, verify object hashes and native rebuild state, and label TCP/emulated storage costs separately. [Support matrix](https://docs.daos.io/v2.8/release/support_matrix/) · [Fault domains and emulation](https://docs.daos.io/latest/admin/hardware/)

## Embedded engines and memory grids

- [ ] **SlateDB — fenced writer on local object storage (new, Rust).** Two separate processes open the same database path in a lab bucket that supports its conditional writes. Hand off ownership during ingest, resume the old writer and verify every durable ACK and stale-writer rejection from a refreshed reader. Report cache/flush visibility separately from object-store durability. [Writer fencing and architecture](https://slatedb.io/docs/get-started/introduction/)
- [ ] **Tidehunter — key distribution and index flush.** Write the same values to Tidehunter and RocksDB using both uniformly hashed IDs and monotonic tenant-prefixed IDs. Select each documented key layout deliberately, reopen after an interrupted flush, and compare exact bodies, read I/O and disk bytes written per logical byte. [Upstream key and index layout](https://github.com/MystenLabs/tidehunter)
- [ ] **Pebble inside CockroachDB — value separation.** Rotate a small hot field among large values, then scan aged rows after compaction at the same replica count and durability. Prove the configured mode and presence of blob files, record disk reads, write amplification and reclamation, and verify row bodies after a node restart. [Storage layer](https://www.cockroachlabs.com/docs/stable/architecture/storage-layer) · [Feature introduction](https://www.cockroachlabs.com/blog/value-separation-cockroachdb-25-3-improved-performance/)
- [ ] **Hazelcast — stale Near Cache during ownership migration.** Read versioned inventory through a cached client while another client updates the partition owner. Stop the owner and compare cached values with direct map reads until convergence. Budget backup copies explicitly. FencedLock with actual CP members is a separate Enterprise-gated design. [CP edition and unsafe-mode boundary](https://docs.hazelcast.com/hazelcast/5.7/cp-subsystem/cp-subsystem)
- [ ] **Chronicle Map — same-host recovery.** Map a file into two processes in a local Linux container lab, kill a writer during updates and reopen a preserved copy with the supported recovery API. Compare recovered pairs with a witness and LMDB under stated flush semantics. Use the native JVM API for this project and keep orchestration outside it. [Project and recovery API](https://github.com/OpenHFT/Chronicle-Map)
- [ ] **Fjall and redb — pinned-reader cost.** Keep a redb read transaction open through conflicting updates. In Fjall scan a stable view through flush/compaction. Release the readers, compare ordered key/value pairs before and after reopen, and measure peak and reclaimed space. Add RocksDB or SQLite only for operations with matching snapshot and sync contracts. [Existing Rust survey](../../rust/EMBEDDED_DATABASE_SURVEY.md) · [Fjall](https://github.com/fjall-rs/fjall) · [redb](https://github.com/cberner/redb)

- [ ] **Apache BookKeeper — fence a ledger writer (new).** Use three bookies and a persistent local metadata quorum. Stop a writer after a confirmed entry, recover and close its ledger through a second client, then resume the former writer. Verify the acknowledged prefix and fencing outcome at declared ensemble/write/ACK quorum settings. Prefer an upstream supported non-Java client where it covers recovery. [Ledger recovery protocol](https://bookkeeper.apache.org/docs/development/protocol/)
