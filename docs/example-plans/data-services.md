# Document stores, search, KV, graphs, edge databases and access control

Each checkbox proposes one independently assignable example or extension. The oracle is what a second process can check after the fault. Each example owns its local services and data. The common execution and evidence requirements are in the [repository guide](../../AGENTS.md).

## Document databases

- [ ] **MongoDB — resume an order feed across an election.** Use a three-member data-bearing replica set, majority-journaled writes and a consumer that persists an event and its resume token together. Step down the primary while issuing order inserts, updates and deletes.
  Compare the resulting materialized orders to the witnessed mutations. Separately let the consumer fall behind the oplog window and exercise a snapshot rebuild. [Change streams and resumption](https://www.mongodb.com/docs/manual/changestreams/)
- [ ] **FerretDB — portable MongoDB applications.** Send the same BSON product catalog to MongoDB and a local FerretDB gateway with the PostgreSQL/DocumentDB extension pair specified in its release notes. Cover absent fields, explicit nulls, nested arrays, typed IDs and updates.
  Restart the gateway during a write and replay only after checking the application ID. Compare exact BSON values and filtered ID sets, with unsupported commands recorded individually. [FerretDB release compatibility](https://github.com/FerretDB/FerretDB/releases)
- [ ] **Couchbase — online stock reservations and the searchable catalog.** Pair inventory and reservation documents in a transaction. Read them through KV and query the secondary index through SQL++ using both default and request-plus consistency.
  Establish the single-node query baseline, then fail a Data node in a three-node replicated deployment. Check conservation of stock and reconcile index visibility lag separately from acknowledged KV durability. [Couchbase transactions, durability and indexes](https://docs.couchbase.com/server/current/learn/data/transactions.html)

## Search

- [ ] **OpenSearch — freshly edited products on relocated shards.** Index the [ESCI corpus](../../datasets/esci/) across three primary shards with replicas. Change prices, descriptions and filters, recording when indexing returns, when GET sees the version and when search sees it with periodic refresh versus `refresh=wait_for`.
  Lose a primary shard's node under traffic. Verify bulk success per item, exact filter/facet counts after refresh and relevance on the held-out judgments alongside [Typesense](../../typesense/product-search/). [Refresh semantics](https://docs.opensearch.org/latest/api-reference/index-apis/refresh/)
- [ ] **Meilisearch — catalog reindex with asynchronous tasks.** Rebuild a local Community index with new typo and filter settings while serving the old catalog. Interrupt a batch and recover or retry by task UID, then swap indexes and check task outcomes, catalog versions and judged search results.
  An optional separate Enterprise trial can place shards and replicas and observe a write-leader outage if the local edition and terms permit it. [Task states](https://www.meilisearch.com/docs/capabilities/indexing/tasks_and_batches/async_operations) · [Shard and replica edition](https://www.meilisearch.com/blog/horizontal-scaling-with-sharding)
- [ ] **Quickwit — searchable immutable log splits.** Stream tenant-tagged events through local Kafka to indexers, PostgreSQL metastore and local S3 storage. Interrupt indexing between object upload and split publication, then observe checkpoint replay while a separate searcher queries older events.
  At a known input offset, reconcile tenant IDs and log bodies, duplicates and publication lag. Compare time/text predicates with Loki and VictoriaLogs, including metastore and storage resources. [Indexing roles, splits and checkpoints](https://quickwit.io/docs/overview/architecture)
- [ ] **Apache SolrCloud — visibility and durability after leader loss.** Route tenant products across a local sharded collection with ZooKeeper. Include a leader-eligible replica and compare NRT and PULL replica visibility around soft and hard commits.
  Fail the shard leader while clients update known versions. Compare per-replica search results after recovery and reconcile acknowledged versions, using the same judged queries as OpenSearch. [Solr commits](https://solr.apache.org/guide/solr/latest/configuration-guide/commits-transaction-logs.html) · [Replica types](https://solr.apache.org/guide/solr/latest/deployment-guide/replica-management.html)
- [ ] **Extend the existing search examples — updates during ranking.** Replay the same product changes during replica replacement in Typesense's application-managed shards and Vespa's native groups, then compare both to the pinned-corpus IDs and judgments. Track old-version hits and availability by shard.
  For Manticore and Elasticsearch, extend the existing *log* comparison with late arrivals and exact tenant/time filters during index recovery. [Typesense evidence](../../typesense/product-search/) · [Vespa evidence](../../vespa/phased-product-search/) · [Manticore and Elasticsearch log workload](../../manticore/log-search/)

## Key-value stores and coordination

- [ ] **Redis 8 — filtered catalog search and vector sets.** Maintain product JSON and a versioned vector fixture. Exercise JSON search and the standalone vector-set commands as separate interfaces, checking exact filters and recall against brute-force neighbors.
  Reopen from a declared persistence mode after a process crash and verify recovered versions and deleted members. Confirm module/command availability in the selected binary. [Vector sets and accuracy controls](https://redis.io/docs/latest/develop/data-types/vector-sets/)
- [ ] **Apache Kvrocks — carts that outgrow RAM.** Hold cart IDs in hashes with skewed reads and expiring items on disk, then restart the writer during compaction. Reconcile each acknowledged field, TTL policy and post-reopen read with a local cart model.
  Extend to slots and a replica to measure traffic during movement, recording which external controller or manual step owns failover. Compare the single-node disk workload with PikiwiDB. [Kvrocks storage](https://github.com/apache/kvrocks) · [Cluster implementation](https://github.com/apache/kvrocks/tree/unstable/src/cluster)
- [ ] **PikiwiDB (Pika) — large hashes under expiry and rewrite.** Populate the same disk-backed cart workload as Kvrocks, then overlap TTL expiry, hash-field rewrites and a snapshot/restart. Verify surviving field bytes, delete visibility and time to space reclamation.
  If the pinned build supports replication, pause a replica and compare its offset and durable contents after catch-up. [PikiwiDB source and supported operations](https://github.com/OpenAtomFoundation/pikiwidb)
- [ ] **Garnet — failover with an asynchronous AOF tail.** Distribute carts across a cluster with an identified primary and replica for each shard. Delay one replica, stop its primary and compare promoted values with the external write journal and offsets.
  Follow with snapshot plus AOF recovery and a cold replica rejoin. Separate replicated loss from successful restore on the old disk. Build on the [existing Lua comparison](../../go/garnet-valkey-lua-comparison/). [Replication protocol and persistence options](https://microsoft.github.io/garnet/docs/cluster/replication)
- [ ] **KeyDB — active-replica conflicts.** In an isolated two-writer pair, partition the replication link and update the same keys, delete/recreate a subset, and update disjoint keys as a control. Keep each writer's accepted values.
  After reconnection check convergence across both replicas, overwritten acknowledgements and client-visible histories. Bound interpretation to the published release used. [Upstream active-replica implementation](https://github.com/Snapchat/KeyDB) · [Releases](https://github.com/Snapchat/KeyDB/releases)
- [ ] **OCache — route large and small cached objects.** Seed reproducible origin bodies on both sides of the small-object RocksDB / large-object disk threshold. On a three-node cache, record native ring ownership, remove an owner and measure misses, remapping and refill cost at the default RF=1.
  Check the body hash on every hit and verify conditional updates against the pinned API. The origin supplies the truth and runs locally. This is a cache lab independent of the Tigris object-store candidate. [Storage layout](https://github.com/tigrisdata/ocache) · [Ring and replication defaults](https://github.com/tigrisdata/ocache/blob/main/docs/cluster.md)
- [ ] **Memcached extstore — flash-backed thumbnail cache.** Replay small metadata and larger thumbnails under a bounded memory budget, with extstore enabled and disabled. Compare warm hit rate, evictions, flash reads/writes and latency under a temporarily slow cache disk.
  Restart and refill from an independent source. Classify cache misses and origin load separately from incorrect bytes on a hit. [Extstore design and operating limits](https://docs.memcached.org/features/flashstorage/)
- [ ] **Cross-system cache comparison — what does the application recover?** Give Valkey, Redis, Dragonfly, Garnet, KeyDB, Kvrocks, PikiwiDB, Tarantool, OCache and Memcached the same logical key trace, TTLs, byte payloads and local origin. Record native protocol, batching, hit/miss accounting and latency per operation.
  First compare the cache contract with refill after owner loss. Run a second durable comparison only on engines with comparable flush/acknowledgement settings and verify every acknowledged body after restart. [Existing Tarantool and Valkey durability profiles](../../tarantool/lua-bench-vs-valkey/) · [Dragonfly layouts](../../dragonfly/)
- [ ] **etcd — revisioned configuration distribution.** Run three voters and workers that range-read a versioned config, then watch from its next revision. Disconnect a watcher past compaction while publishing more versions and changing lease holders during leader loss.
  Prove the watcher recovers via fresh revision plus watch, check CAS/version histories and have the downstream resource reject stale fencing tokens. [API guarantees](https://etcd.io/docs/v3.6/learning/api_guarantees/) · [Watch RPC implementation](https://github.com/etcd-io/etcd/blob/main/server/etcdserver/api/v3rpc/watch.go)
- [ ] **Apache ZooKeeper — fencing a former worker.** Build a three-member ensemble where contenders use ephemeral sequential nodes and predecessor watches. Pause the holder beyond its session timeout, elect a successor and deliver the former holder's delayed work to a local service.
  Verify monotonic application fencing at that service, record session expiration and re-election time, and compare with the etcd lease workload. [ZooKeeper locks and recoverable errors](https://zookeeper.apache.org/doc/r3.9.6/recipes.html)
- [ ] **Oxia — sharded ownership metadata.** Spread stream ownership across native shards, use versioned updates and attach worker liveness to sessions. Replace a shard leader while notification consumers and unrelated shards carry traffic.
  Check version order within the promised scope, expiry of ephemeral records, client resynchronization and full per-key readback. Compare with etcd using the same ownership requests. [Notifications](https://oxia-db.github.io/docs/features/notifications) · [Ephemeral records](https://oxia-db.github.io/docs/features/ephemerals)
- [ ] **Ignite 2 — colocated inventory transactions.** Key warehouse stock and reservations by the same affinity key, with controls that span warehouses. Run transactional reservations and a per-warehouse valuation while a persistent server leaves and rejoins.
  Reconcile reservations plus remaining stock and observe partition placement and rebalance duration. Compare with PostgreSQL and the transactional subset of the Hazelcast grid workload. [Affinity colocation](https://ignite.apache.org/docs/ignite2/latest/data-modeling/affinity-collocation)
- [ ] **Ignite 3 — loss of a distribution zone's replication majority.** Place the same stock/reservation workload in a replicated zone, record partition assignments, then take a majority offline and bring the original copies back. Check which keys remained available and whether every committed reservation survived.
  Exercise any destructive partition reset only on another copy and quantify its RPO. Treat 3.x as a research comparison with 2.x under the stated upstream maintenance status. [Partition recovery](https://ignite.apache.org/docs/ignite3/latest/administrators-guide/disaster-recovery) · [Release status](https://ignite.apache.org/download/)
- [ ] **Infinispan — site isolation with asynchronous backups.** Run two local site groups, distribute carts inside each site, interrupt the inter-site link and issue conflicting and disjoint updates. Capture the selected backup and merge policies before the fault.
  Reconnect, request state transfer if required and compare both sites with the expected conflict winners, expired entries and tombstones. [Cross-site replication, merge and state transfer](https://infinispan.org/docs/stable/titles/xsite/xsite.html)

## Graph and multi-model databases

Use the [Memgraph and Neo4j fraud fixture](../../memgraph/fraud-detection/) as a starting point. Save a language-neutral list of planted rings and expected reachable account IDs so different query languages can be checked against the same graph.

- [ ] **LadybugDB — embedded investigation snapshot.** Import transfers into a local graph file and trace exposure from flagged accounts while a transaction adds ring-closing edges. Crash the owning process and reopen the same database.
  Check exact edge bodies and canonical ring sets before and after commit. Measure ingest and traversal separately from file reopen. [Embedded engine and Cypher support](https://github.com/LadybugDB/ladybug)
- [ ] **ArcadeDB — document and graph writes in one transaction.** Persist a payment document and its payer/payee edges atomically, then read the payment by ID and traverse from each account. Use an HA configuration with a declared write quorum.
  Interrupt the leader during commits, reconcile ambiguous IDs and verify that every committed payment has exactly the expected edges and payload after election. [ArcadeDB HA setup, write quorum and recovery](https://docs.arcadedb.com/arcadedb/how-to/operations/ha)
- [ ] **SurrealDB — enforce graph endpoint integrity.** On a local file-backed engine, model devices as records and account links as relations, trying the default and an `ENFORCED` relation table with absent endpoints. Include delete and re-create cases in an explicit transaction.
  Crash/reopen and verify graph traversal and stored records against the expected witnesses for each schema. [RELATE and endpoint enforcement](https://surrealdb.com/docs/reference/query-language/statements/relate)
- [ ] **Dgraph — concurrent identity upserts.** Write the same external account ID from two clients using an indexed upsert predicate, with retries on transaction conflicts. Track logical IDs independently from Dgraph UIDs.
  Repeat on a replicated Alpha group through leader loss. Verify each identity resolves to exactly one UID and all acknowledged links survived. [DQL upserts](https://www.dgraph.io/dql/upserts/) · [Alpha, Zero and groups](https://docs.dgraph.io/installation/dgraph-architecture/)
- [ ] **FalkorDB — many tenant graphs on hash slots.** Keep one fraud graph per tenant, distribute graph keys across primaries and confirm their owners. Fail the primary for a busy tenant while other tenants continue querying their own rings.
  After promotion compare per-tenant edge bodies and rings, measure lost writes allowed by async replication and verify tenant isolation. A single graph resides on one shard. [Cluster storage unit and failover](https://docs.falkordb.com/operations/cluster)
- [ ] **TigerGraph Community — deep-link investigation on one server.** Compile a GSQL traversal for common-device exposure and exact canonical fraud rings. Add late payments, restart the licensed local instance and rerun the traversal against the independent edge list.
  Check the available image architecture and record emulation. The Community result covers single-server execution. [Edition limits](https://www.tigergraph.com/pricing/) · [Community image](https://hub.docker.com/r/tigergraph/community)
- [ ] **TypeDB — typed payment relations.** Bind payer, payee and device roles explicitly, submit valid transfers and cases violating the schema, then use a TypeQL function to find related accounts through two hops.
  After restarting a local Community server, compare exact role bindings and transfer IDs with the oracle, and verify rejected transactions left no partial relations. [TypeQL concepts](https://typedb.com/docs/core-concepts/typeql/overview/)
- [ ] **JanusGraph on Cassandra — edge/index divergence.** Write transfers and indexed external IDs through Gremlin, including concurrent inserts of one identity. Declare Cassandra consistency levels and the JanusGraph locking/consistency settings for the relevant schema.
  Interrupt one Cassandra replica during mutations. Check direct vertex lookups, directional edges and indexed queries independently after recovery. [Consistency, locking and repair limits](https://docs.janusgraph.org/advanced-topics/eventual-consistency/)

## Embedded and edge databases

- [ ] **Turso Database — SQLite compatibility at the application boundary.** Run the same local inventory SQL, constraints, transactions and competing reservations against the Rust engine and SQLite. Match acknowledgement settings and separate optional/experimental features by build.
  Kill the writer between a reservation and its receipt and reopen the owned file. Check units, types, rows and commit outcomes against an external journal. [Turso engine](https://github.com/tursodatabase/turso/tree/main/core) · [Prior repository survey](../../rust/EMBEDDED_DATABASE_SURVEY.md)
- [ ] **rqlite — choose a read level during leader loss.** Place the same inventory ledger on three voting nodes and sample reads from each member at explicit read consistency levels while writes continue. Partition the old leader and reconnect it.
  Reconcile committed rows, permitted staleness and unavailable reads per level. Use an actual networked Raft write path as the comparison boundary. [Read consistency levels](https://rqlite.io/docs/api/read-consistency/)
- [ ] **LiteFS — single-writer failover with an asynchronous replica.** Put SQLite behind local FUSE mounts and a supported local lease service. Delay the replica, lose the primary and exercise write forwarding plus recovery of an old primary.
  Record position differences, rejection of writes on read-only nodes and acknowledged IDs missing after promotion. Check local FUSE prerequisites and Fly's support notice before assigning this lab. [LiteFS architecture and support status](https://docs.fly.io/litefs)
- [ ] **Litestream — restore an edge shop from backup.** Replicate a different local SQLite fixture into a private local S3-compatible store. Interrupt the archive connection, then restore a chosen recovery point into a new directory with the source unavailable to the restored application.
  Reconcile order IDs and values at the chosen point, and report the age and size of the unarchived tail. This measures independent backup RPO and RTO. [Litestream replication and restore model](https://litestream.io/how-it-works/)
- [ ] **Embedded KV comparison — LMDB, libmdbx, Badger, Pebble and bbolt.** Use a Go adapter per engine to insert versioned pairs atomically, seek a prefix and iterate a consistent read view. Pin sync options, readers and batch size for each engine.
  Hold a read view during churn, crash the writer and compare ordered keys, values, acknowledged pairs, retained pages and write amplification. Limit the shared contract to operations all adapters support. [LMDB binding](https://github.com/PowerDNS/lmdb-go) · [libmdbx](https://github.com/Mithril-mine/libmdbx) · [Badger](https://github.com/dgraph-io/badger) · [Pebble](https://github.com/cockroachdb/pebble) · [bbolt transactions](https://github.com/etcd-io/bbolt/blob/main/tx.go)

## Identity and access

- [ ] **Keycloak / ZITADEL / authentik — signing-key rotation for local login.** Issue OIDC tokens to the same test users on each local provider with identical audiences and lifetimes, rotate keys and restart the issuer while a relying party uses cached JWKS. Give SAML assertions their own validation flow where included.
  Check allowed/denied outcomes and token expiry using issued fixtures. Compare offline signature checks with online introspection after revocation and measure provider dependency separately. [Keycloak admin guide](https://www.keycloak.org/docs/latest/server_admin/) · [ZITADEL keys](https://zitadel.com/docs/guides/integrate/login/oidc/webkeys) · [authentik OAuth provider](https://github.com/goauthentik/authentik/tree/main/authentik/providers/oauth2)
- [ ] **SpiceDB / OpenFGA — permissions immediately after revocation.** Model a folder tree with group sharing and inherited access in each system's own schema. Revoke a group grant while readers continue checks against two service instances and an owned PostgreSQL backend per trial.
  Check against a reference graph and record allowed staleness separately for SpiceDB's ZedToken-bound reads and OpenFGA's higher-consistency/cache preferences. Include a client reconnect after a service restart. [SpiceDB semantics](https://authzed.com/docs/spicedb/concepts/consistency) · [OpenFGA semantics](https://openfga.dev/docs/interacting/consistency)
- [ ] **OPA / Cedar — tenant authorization through a policy rollout.** Encode the same explicit permit/deny table in Rego and Cedar and evaluate recorded requests for tenant boundaries, overrides and missing attributes. Pin the input-to-entity mapping.
  Interrupt distribution of a new policy version, record the policy revision actually used for every decision and verify recovery against the expected table for each version. [Rego](https://www.openpolicyagent.org/docs/policy-language) · [Cedar decision rules](https://docs.cedarpolicy.com/auth/authorization.html)
- [ ] **Teleport — short-lived local access and auditing.** Give fixture users separate roles for a local SSH target and database, issue short-lived credentials and test allow/deny decisions around expiry and an auth-service restart. Add access to a disposable kind cluster as a second target.
  Verify SSH session playback and the available protocol-specific audit events for database and Kubernetes actions. Check binary licensing for the selected edition. [Recording modes and coverage](https://goteleport.com/docs/reference/architecture/session-recording/) · [Community Edition terms](https://goteleport.com/blog/teleport-community-license/)
